M98 smoke test — browser runner

There is no Node on this machine, so smoke-test.mjs had never been executed — it was verified by being parsed, which is not the same thing. This page runs it in the browser's own JavaScript engine instead. It does not reimplement the harness. It reads smoke-test.mjs as text, rewrites four lines that only Node can satisfy, and runs the rest exactly as written, so a check that passes here is the same check.

Serve this folder over HTTP and press run — fetch cannot read a sibling file from file://.

What is rewritten, and nothing else. (1) the #! shebang, which Node strips and a browser cannot parse; (2) import fs from 'node:fs' — fs.readFileSync is replaced by a fetch of the deck; (3) every globalThis.document becomes a bare document, because a browser will not let a page replace its own — assignment silently fails and defineProperty throws Cannot redefine property, so the stub is passed in as a function parameter instead and the harness reads it through the scope chain; (4) globalThis.setInterval likewise, so the deck's tick is captured rather than the page's real timer being clobbered. process.exit throws instead of exiting, and the throw is caught and reported. Nothing else is touched — in particular globalThis.DD, globalThis.ddb and every globalThis.dd* entry point stay real globals, because that is where the deck blocks actually put them.

What this is not. It is not a second engine and it is not a second copy of anything — if it ever disagrees with node smoke-test.mjs, the Node run is the answer and this page is the bug. The deck's globals land in this page's global scope, so reload between runs rather than pressing run twice. Storage is cleared before each run and restored after, so a run starts from the tool's defaults and the drills you have banked on this origin survive.
