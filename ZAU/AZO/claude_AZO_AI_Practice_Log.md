# AZO AI-Assisted Practice Log

**Status, 2026-10-28: empty. No AZO drill has been flown.**

The running record of drills run with the AI coach, mirroring `../C90/claude_C90_AI_Practice_Log.md`.

## The ledger rule

> **One ledger, no second class.**

AZO has no `PRIOR` array and no `hist()`. The in-tool ledger is `ddb.state.entries`: the debriefs written with *Bank it* and saved under `azo-drill-deck-v1`. It is empty, and the smoke test asserts it. A drill recorded here is also typed into the tool, so the two cannot drift. **A scrapped drill still counts.**

## Entry format

Newest first, one section per session.

```
## YYYY-MM-DD — <what was built> + Drill N (<sector>)

**Frame:** sector · frequency · fields it works · who else is open · East Wall
neighbour · flight category · what the traffic was

**Drill N — <one-line description>**

- What was built or changed in the tool that session, if anything.
- What the drill put in front of the trainee.
- **Strengths shown** — specific, with the callsign and the moment.
- **Watch-fors** — the thing to do differently.
- **Standing items moved** — none exist yet.
- **Why** — the line from the session notes. Quote it.
- **Suggested next reps.**
```

## The frame is different from M98's

No configuration, no combining chain, two walls, a 10,000 ceiling, and no procedure to fly (overflights only). See `claude_AZO_Drill_Format.md`.

## Before the first entry

Standing items come from `claude_AZO_OJT_Session_Review.md`, which needs a session. Logging drills against invented items would corrupt the ledger permanently.
